# 审查指南 · 第二部分 第九章 关于涉及计算机程序的发明专利申请审查的若干规定

> 来源层：《专利审查指南》（2023年版）｜本章 ID：`gl-p2-ch09`｜同一主题在另两层的章节见文末「关联」；条文级对照见 [crosswalk.md](../crosswalk.md)

## 核心要点
涉及计算机程序的申请须过两道客体门：不是「智力活动的规则和方法」（法25.1(2)），且构成技术问题—技术手段—技术效果齐备的「技术方案」（法2.2）（第2节）。含算法特征或商业规则和方法特征的申请以权利要求全部特征为整体审查，只有与技术特征「功能上彼此相互支持、存在相互作用关系」的算法或商业规则特征才计入创造性贡献（第6.1节）。

## 引入的框架

### 一、定义（第1节）
- 计算机程序本身：可由信息处理装置执行的代码化指令序列，或可自动转换为其的符号化指令/语句序列，含源程序和目标程序。
- 涉及计算机程序的发明：全部或部分以程序处理流程为基础，通过执行程序对外部对象（外部过程或装置、外部数据）或内部对象（内部性能、内部资源、数据传输）进行控制或处理的解决方案；不必须改变硬件。

### 二、客体第一步：法25.1(2) 智力活动的规则和方法（第2节、第6.1.1节）
- 何时用：逐项针对每项权利要求所限定的解决方案；属第一章第4.2节情形的按该节原则。
- 怎么判断：(1) 仅涉及算法或数学计算规则、程序本身、仅记录在载体上的程序本身、游戏的规则和方法 → 排除；除主题名称外全部限定内容仅涉及上述内容的「实质上仅仅涉及」，同样排除（仅由程序限定的存储介质或程序产品、仅由游戏规则限定的游戏装置）；介质涉及叠层构成、磁道间隔、材料等物理特性改进的除外。(2) 既含智力活动规则又含技术特征 → 整体上不是智力活动的规则和方法，转法2.2审查。
- 第6.1.1节同理：抽象算法或单纯商业规则且不含任何技术特征的才排除（如纯返利规则）。

### 三、客体第二步：法2.2 技术方案三要素（第2节、第6.1.2节）
- 判断标准：执行程序的目的是解决技术问题；对外部或内部对象的控制或处理反映遵循自然规律的技术手段；获得符合自然规律的技术效果。缺一即非技术方案。三类典型：工业过程、测量或测试过程控制；处理外部技术数据；改善计算机系统内部性能。
- 第6.1.2节对算法/商业规则特征的路径（整体考虑、不割裂）：① 算法处理的是技术领域中具有确切技术含义的数据，其执行直接体现利用自然规律解决技术问题的过程 → 通常属技术方案；② 深度学习、分类、聚类等算法改进与计算机系统内部结构存在特定技术关联，解决提升硬件运算效率或执行效果的技术问题 → 属技术方案；③ 处理具体应用领域大数据，以分类、聚类、回归分析、神经网络等挖掘符合自然规律的内在关联关系，提升该领域分析可靠性或精确性 → 属技术方案；④ 反面：问题取决于人的主观意愿或经济学规律、手段是按人为规则计算、效果不受自然规律约束 → 非技术方案（第6.2节例8～10）。

### 四、汉字编码方法（第4节，法25.1(2)）
汉字编码方法是信息表述方法：问题取决于表达意愿、手段为人为编码规则、结果仅为符号/字母数字串 → 排除。与其可使用的特定键盘结合、使计算机以汉字信息为指令运行程序的计算机汉字输入方法或汉字信息处理方法 → 技术方案；说明书和权利要求书应描述输入方法的技术特征，必要时含键盘各键位定义及位置。

### 五、说明书（第5.1节，法26.3；第6.3.1节）
- 必须清楚、完整描述程序的设计构思、技术特征及实施方式；附图给出主要流程图，按流程时间顺序用自然语言逐步骤描述；尺度是本领域技术人员能据流程图及说明编制出达到所述技术效果的程序；可短摘录关键源程序，不需提交全部。含硬件结构改变的，给出硬件实体结构图并描述各硬件组成及相互关系。
- 含算法特征时，至少一个输入参数及其相关输出结果的定义应与技术领域中的具体数据对应关联；含商业规则和方法特征时，详细描述解决技术问题的整个过程；有益效果写质量、精度、效率提高或内部性能改善；用户体验提升可写，但须说明如何由技术特征及与其相互支持的算法/规则特征共同带来（第6.3.1节）。

### 六、权利要求书（第5.2节，法26.4、细则20.2；第6.3.2节）
- 可写成方法权利要求或产品权利要求（实现该方法的装置、计算机可读存储介质、计算机程序产品）。任何形式都须得到说明书支持、整体反映技术方案、记载必要技术特征，不能只概括描述程序功能及效果；方法项按流程步骤写各项功能及如何完成，装置项写各组成部分及关系（可含硬件也可含程序）。
- 与程序流程各步骤（或方法权利要求各步骤）完全对应撰写的装置权利要求，其组成部分理解为实现各步骤所必须建立的程序模块，整体理解为「程序模块构架」而非硬件实体装置；计算机程序产品理解为主要通过程序实现解决方案的软件产品。
- 【例4】四件套：方法；计算机装置/设备/系统（存储器、处理器及存储的程序，处理器执行以实现权利要求1的步骤）；计算机可读存储介质（存储的程序/指令被处理器执行时实现权利要求1的步骤）；计算机程序产品（包括程序/指令，同上）。
- 第6.3.2节：权利要求应记载技术特征以及与其相互支持的算法或商业规则和方法特征。

### 七、新颖性与创造性（第6.1.3节，法22.2、22.3）
- 新颖性：考虑权利要求记载的全部特征，包括算法特征或商业规则和方法特征。
- 创造性：与技术特征「功能上彼此相互支持、存在相互作用关系」的算法/商业规则特征与技术特征作为整体考虑；该关系指两类特征紧密结合、共同构成解决某一技术问题的技术手段并获得相应技术效果。三种认定情形：算法应用于具体技术领域、解决具体技术问题；算法与计算机系统内部结构存在特定技术关联、提升硬件运算效率或执行效果（例15）；商业规则和方法特征的实施需要技术手段的调整或改进（例13）。用户体验提升由技术特征、或由技术特征与相互支持的算法/规则特征共同带来的，应予考虑。
- 操作顺序（第6.2节例11～15）：确定区别特征 → 判断其中算法/规则特征是否与技术特征相互支持 → 据此确定「发明实际解决的技术问题」→ 判断现有技术整体是否给出启示；相互支持不等于非显而易见（例12 Messy 遗传算法：对比文件2已给出启示，仍不具备创造性）。

## 关键概念
- 计算机程序本身 — 可执行或可自动转换为可执行的指令/语句序列，单独主张即为智力活动的规则和方法（第1、2节）。
- 智力活动的规则和方法 — 算法、程序本身、游戏规则、信息表述方法等不含技术特征的方案，依法25.1(2)排除（第2、4节）。
- 技术方案三要素 — 解决技术问题、利用遵循自然规律的技术手段、获得符合自然规律的技术效果（第2节）。
- 算法特征／商业规则和方法特征 — AI、「互联网＋」、大数据、区块链类申请中属智力活动规则性质的特征，不得与技术特征简单割裂（第6.1节）。
- 功能上彼此相互支持、存在相互作用关系 — 算法/规则特征与技术特征紧密结合、共同构成解决技术问题的技术手段并获得技术效果（第6.1.3节）。
- 具有确切技术含义的数据 — 图像像素、传感器信号、自然语言文本等技术领域数据，算法处理此类数据是客体成立的主路径（第6.1.2节）。
- 符合自然规律的内在关联关系 — 大数据挖掘所得关联须受自然规律而非经济学规律支配（第6.1.2节）。
- 计算机系统内部性能改进 — 减少数据存储量、减少数据传输量、提高硬件处理速度等，算法与内部结构有特定技术关联时成立（第2、6.1.2节）。
- 程序模块构架 — 与流程步骤一一对应的装置权利要求的法定解读，非硬件实体（第5.2节）。

## 思维模型
- 看到「由计算机执行的…方法」想「三问」：问题是技术的还是人为、商业、经济的？对计算机的限定是否只是「按人为规则算」？效果是否受自然规律约束？例8返利、例9经济景气、例10金融价格都在第一问出局（第6.1.2节）。
- 看到 AI／大数据算法想「数据是谁的」：图像、文本、传感信号 → 例2、例7路径；抽象通用数据且无技术特征 → 例1落法25；金融、经济数据 → 关联不符合自然规律，例10路径（第6.1.2节）。
- 看到区别特征是算法或规则想「拆掉它，技术手段变不变」：不变（例14情感分类规则）→ 无相互作用、不计贡献；变（例13批量通知迫使数据架构与通信方式调整）→ 整体考虑并重定实际解决的技术问题（第6.1.3节）。
- 看到存储介质／程序产品权利要求想「介质本身改了什么」：仅以程序限定 → 法25排除；挂靠已成立的方法权利要求（被处理器执行时实现其步骤）→ 允许（第2、5.2节）。

## 反模式
- 把主题名称当技术特征：例3「利用计算机」只在主题名称，限定内容全是人为录入规则，仍落法25.1(2)（第3节）。
- 把「与物理量有关」误当技术手段：例2动摩擦系数，过程是纯数值计算，未改进测量方法（第3节）。
- 割裂技术特征与算法/商业规则特征、把后者一概忽略（第6.1节禁止）；或反向不检验相互作用关系就把所有算法特征计入贡献（第6.1.3节）。
- 说明书只写功能与效果、无流程图和步骤描述 → 法26.3不充分；算法输入输出不与具体技术数据关联 → 客体与公开双重风险（第5.1、6.3.1节）。
- 单独主张「用户体验提升」而不说明其由技术特征或相互支持的算法/规则特征带来（第6.1.3、6.3.1节）。

## 实例演练
- 第3节例4 vs 例8：控制橡胶模压成型工艺——采样硫化温度→计算正硫化时间→达到即发终止信号，防过/欠硫化（技术问题）、按硫化原理实时控制（技术手段）、产品质量提高（技术效果）→ 工业过程控制型技术方案。计算机游戏方法——答对则升级角色等级、装备，装置公知、未改进内部性能或装置构成，问题是按人的主观意志兼顾两类游戏，手段是人为活动规则，效果只是游戏过程管理 → 非技术方案；因含技术特征不落法25，而由法2.2排除。
- 第6.2节例6 vs 例10：电子券使用倾向度分析——用户行为特征（浏览时长、搜索次数、用券频率）与使用倾向度的内在关联符合自然规律，解决提升分析精确性的技术问题 → 技术方案。金融产品价格预测——同用神经网络挖掘大数据，但价格走势遵循经济学规律，历史与未来价格间不存在符合自然规律的内在关联 → 非技术问题，不属技术方案。
- 第6.2节例11 vs 例14（创造性）：仿人机器人跌倒检测——区别为模糊决策算法，以姿态、ZMP、步行阶段传感信息为输入、输出稳定性判定供姿势调整 → 与技术特征相互支持，实际解决的技术问题为判断稳定状态并预测跌倒方向，算法及其应用未被公开且非公知常识 → 具备创造性。动态观点演变可视化——区别仅为情感分类规则（点赞/点踩比值阈值），着色等可视化手段不因规则改变 → 无相互作用，仅提出新规则、未解决技术问题 → 不具备创造性。

## 关键要点
1. 客体两步且顺序固定：先法25.1(2)，含任何技术特征即通过；再法2.2三要素逐项检验（第2、6.1.1、6.1.2节）。
2. 「技术问题」最常成为拦路石：把问题定义为物理、工程或系统性能问题（速度、精度、存储量、传输量、安全性），不要定义为商业、经济或用户意愿问题；大数据类申请自查关联关系是否符合自然规律，经济学规律不算（第6.1.2节）。
3. 算法必须落地：说明书至少一组输入输出定义对应技术领域具体数据，权利要求写明数据的技术含义（第6.1.2、6.3.1节）。
4. 创造性先问相互作用关系：算法/规则特征换掉后技术手段是否必须调整；有则整体评价并重定实际解决的技术问题，无则不计贡献；相互支持不等于非显而易见（第6.1.3节、第6.2节例12）。
5. 权利要求按四件套布局，产品项以「被处理器执行时实现权利要求1的步骤」挂靠方法；需硬件实体保护的须写实体结构并配硬件实体结构图，否则被读作程序模块构架（第5.1、5.2节）。
6. 说明书必须有主要流程图和按时间顺序的步骤描述，以本领域技术人员能编制出程序为尺度（第5.1节）。
