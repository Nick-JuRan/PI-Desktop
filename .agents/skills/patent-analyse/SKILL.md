# patent-analyse

在当前工作区内，把用户提供的专利申请材料整理成可追溯的 Markdown 文件，并对指定权利要求执行“理解发明”分析。

## 适用范围

- 输入是用户当前任务提供的申请文件、OCR 文本或申请材料文件路径。
- 输出始终写入当前工作区的相对目录 `reports/`；不要创建新的项目目录或切换到其他工作区。
- 只使用申请材料中的事实。缺失字段留空，并在回执中列出；不要猜测申请号、日期、人员、分类号、关键词或技术效果。
- 没有指定权利要求编号时，默认分析权利要求 1。用户指定 `x` 时只分析权利要求 `x`。

## 固定编排

主代理必须按顺序委派两个全局子代理定义，并等待第一个完成后再启动第二个：

1. 使用 `Task` 启动 `patent-splitter`。在委派提示中传入：当前工作区、所有申请材料的路径或完整文本、用户指定的权利要求编号（如有），并要求它读取全部材料。
2. 使用 `TaskWait`（或宿主提供的等价等待工具）收集 `patent-splitter` 的完整回执。先向主代理报告其 `status` 和 `missing`，但 `partial` 不得阻止下一步。
3. 无论第一阶段是否有缺失，只要已经得到报告目录，就立即使用 `Task` 启动 `patent-analyst`。传入第一阶段返回的 `report_dir`、`申请文件`目录和目标权利要求编号；不得把未整理的原始材料路径误当作分析输入。
4. 等待 `patent-analyst` 回执，核对输出路径和状态；最后向用户报告两个阶段的状态、缺失清单和生成的文件路径。

不得并行启动两个子代理：第二个代理依赖第一个代理建立的目录和三个申请文件。不得用主代理自行改写子代理回执来假装完成。

## 期望文件树

`patent-splitter` 必须在当前工作区创建：

```text
reports/
└── <发明名称>/
    └── 申请文件/
        ├── 基本信息.md
        ├── 权利要求书.md
        └── 说明书.md
```

完成理解分析后追加：

```text
reports/
└── <发明名称>/
    └── 理解发明/
        └── 权<x>.md
```

发明名称以申请文件原文为准。Windows 不允许的文件名字符只能替换为 `_`；原始名称必须保存在 `基本信息.md`，并在回执中说明替换。已存在的 `reports/` 或发明目录中的其他文件不得删除。

## 子代理职责边界

- `patent-splitter` 负责读取全部申请材料，整理出供下游使用的申请文件，并报告缺失、冲突和 OCR 问题；不做新颖性、创造性、IPC/CPC 或外部检索。
- `patent-analyst` 负责基于 `patent-splitter` 的申请文件，对指定权利要求执行“理解发明”分析并写入报告；只使用申请文件事实，不做外部检索或无依据推断。具体报告格式和字段要求以 `patent-analyst` 的子代理提示词为准。
- 从属权利要求可以读取其引用的父项以理解上下文，但报告中心仍是指定权利要求，不得无提示扩大保护范围。
- 两个子代理完成后都必须输出其定义中规定的 XML 回执；主代理应原样保留 `missing` 和 `notes` 的信息。

## 输入异常

- 材料没有提供或路径不可读时，先向用户说明缺少的输入，不要编造申请文件或创建伪造分析结果。
- 材料部分可读时，仍让 `patent-splitter` 写出三个目标文件，将无法确认的字段留空；随后继续委派 `patent-analyst`。
- 多份材料出现冲突时保留证据并在回执中说明，不能静默选择其中一份。

## 完成门槛

主代理只有在实际检查到下列结果后才能报告完成：

1. `patent-splitter` 已返回有效的 `report_dir` 和 `material_dir`，且三个申请文件均存在；
2. `patent-analyst` 已返回目标权利要求的 `理解发明/权<x>.md`；
3. 两个子代理的 `status`、`missing` 和 `notes` 回执信息均已保留并核对。
